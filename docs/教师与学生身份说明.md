# 教师与学生身份（2026-09-20 用户确认的增补规则）

本说明增补原 V1 文档；首次正式成绩、逾期完成、Owner 排除、邀请码加入等原规则不变。

## 账号与权限

- 微信 OPENID 登录身份不变，无需额外的账号密码。新用户的 `users.accountRole` 为 `student`；老用户缺少字段时也按学生展示。
- 学生首页提供邀请码加入和学习任务。个人资料页可输入教师开通码，成功后进入教学工作台。
- 教师身份只允许创建小组，不赋予其他小组管理权。所有原 Owner 操作仍由服务端核对 `groups.ownerId`。
- 原有小组、成员和成绩不迁移、不删除。已有 Owner 仍保留对已有小组的权限；创建新组和使用新教学工作台需要开通教师身份。教师仍可通过“全部小组”访问自己作为 Member 加入的其他小组，保留原文档跨组身份规则。
- 预览首页是教师自己发布的任务集合，不冒充某位真实学生。预览接口仅允许已开通教师身份的本组 Owner 读取已发布任务；草稿和撤回任务不能预览。
- 预览记忆、默写、错词练习都在独立页面内存中运行，不调用正式提交、进度或练习写接口。体验评分仅用于展示；学生正式成绩仍由云函数评分。

## 首次部署

1. 在云数据库创建 `teacher_activation_codes` 集合，权限设置为客户端不可读、不可写（同 `security-rules.json`）。`users` 也必须保持客户端不可写。
2. 在本地执行 `node scripts/generate-teacher-code.mjs`。生成 128 位随机开通码及其 SHA-256 摘要，不会写入仓库。
3. 按脚本输出手动新建云数据库记录：`_id` 为 64 位摘要字符串；`status` 为字符串 `active`；`expiresAt` 必须选择 **Date 类型**，设置为约 7 天后的时间（脚本提供参考时间戳）。不要把明文开通码存到记录里。
4. 只把明文码私下给一位教师，不要发到学生群，不要提交 Git。每个码仅能开通一个账号。可将尚未使用的记录状态改为 `revoked` 来作废；不会撤销已开通账号。
5. 运行 `npm run build:cloud`，重新上传部署 auth、group、task、study、attempt 五个云函数（共享身份/成员查询代码有变更），然后重新编译小程序。
6. 教师进入“我 → 教师开通”，输入开通码；成功后自动进入教学工作台。

无有效开通码时保持学生身份，不能通过前端传入 role/accountRole 提权。开通通过事务锁定开通码与用户，同一码并发兑换只允许一个用户成功；同用户成功重试不重复消费。每账号 15 分钟最多 5 次格式合法但无效的开通尝试。

## 验收

- 新学生看不到创建小组入口；直接调用 group.create 也返回 TEACHER_REQUIRED。
- 无效、过期、已使用、作废的码不可开通；重复请求不降级账号；昵称修改不能修改身份。
- 教师重进自动进入教学工作台；只能操作自己创建的小组。
- 学生邀请码加入、逾期提交、首次成绩锁定、错词练习不改分保持不变。
- 发布任务后可从工作台预览入口或任务详情进入学生预览。完成体验后数据库的进度、正式提交、练习和排名记录均不增加。
- 在开发者工具和真机检查小组名称、任务标题、默写输入框，确认文字完整、键盘弹出后仍可滚动操作。

本地自动化检查不能代替云端真实多账号和真机验收。
